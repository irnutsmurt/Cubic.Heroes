# Developer setup

## What you need
- A decrypted dump of your own **BLUS-30490 v01.00** disc (see
  `config/game_version.json` for the expected size and SHA-256).
- Either an `EBOOT.elf` you decrypted yourself, or a keys file for
  `tools/self_decrypt.py`. Keys are never part of this repository. The file
  format is one line per key revision:
  `APP <revision-hex> <erk 64 hex> <riv 32 hex>`.
  This disc needs revision `0x0001`.
- Linux: clang ≥ 14 or GCC ≥ 12, CMake ≥ 3.20, Ninja, SDL2, Vulkan headers,
  glslang, Python ≥ 3.10 with `pycryptodome`.
- About 10 GB free disk: extracted disc 3.3 GB, generated C++ 172 MB, objects
  and binaries several GB.

## Pipeline
```bash
python3 -m venv build/venv && build/venv/bin/pip install pycryptodome
git clone https://github.com/sp00nznet/ps3recomp build/ref/ps3recomp
git -C build/ref/ps3recomp checkout 4e8f3ca
build/venv/bin/python tools/pipeline.py --iso "<your image>.iso" --keys <keys.txt>
```
The stages are listed in `tools/pipeline.py`. Each is skipped when its outputs
are newer than its inputs.

Everything lands under `build/`, which is git-ignored:

| Path | Contents |
|---|---|
| `build/disc/` | Extracted disc, Joliet names |
| `build/EBOOT.elf` | Decrypted executable |
| `build/gen/out/` | Function, import and image manifests |
| `build/gen/recompiled/` | Lifted PPU C++, 48 stable chunks plus table |
| `build/gen/spu/` | Lifted SPU images and `spu_workloads.c` |
| `build/port/ppu_hle_nids.cpp` | NID → HLE handler table (generated by the port build) |

## Rules
- Never commit anything under `build/`, any key material, or game files.
- Big outputs belong under `build/`, never `/tmp` (tmpfs on the dev machine).
